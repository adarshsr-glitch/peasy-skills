# Product documents for Peasy

Use a Claude Doc unless the user names Word. Write in the language the user writes in; UI strings inside the doc in Dutch with French alongside or flagged as to-do.

## PRD
1. Summary
2. Problem and evidence (facts vs assumptions marked)
3. Users and jobs-to-be-done (Belgian households; vertical: mortgage, insurance, energy, internet/TV)
4. Goals and non-goals
5. Requirements
6. User stories ("Als [gebruiker] wil ik [actie], zodat [resultaat]" or English if the team writes English)
7. Acceptance criteria (Given/When/Then), including validation, error, empty, accessibility
8. States and edge cases
9. Success metrics (no invented numbers)
10. Dependencies, legal and privacy (consent, required disclaimers for financial products)
11. Open questions
12. Release notes

## Screen or component spec
Name and purpose · user and context · layout regions in order · Peasy components used (by name) and new ones marked proposed · content in nl-BE (+ fr-BE) · primary and secondary action · states · responsive rules · accessibility · open questions.

## Flow
Goal and entry point · ordered steps (user action → system response) · branches, validation, error recovery, cancel, save progress · success · the Peasy 3-step pattern (vergelijk → kies → regel) where it applies.

## Hand-over
Link to the design (only if actually created) · tokens and components referenced · proposals list · states · acceptance criteria · assets used (asset names from the system) · open decisions.

Onboard a new energy supplier: compare and switch via API

Summary

Peasy compares energy suppliers, but every new partner is wired in by hand. This epic defines a reusable way to add a new supplier ("Leverancier X"): pull its tariffs every night from its API, show them in the results for Flanders, Wallonia and Brussels ranked neutrally by price, and submit the customer's switch straight to the supplier's order API. It becomes the template for each future energy supplier.

Context

  • Today's energy flow asks for postcode, solar panels, single/dual meter, electricity and gas usage, current supplier and green preference. Peasy then arranges the switch.
  • A switch keeps the 35-day legal notice and the meter stays the same. Peasy re-checks for better deals every year.
  • Prices and grid operators differ by region. Regulators: VREG (Flanders), CWaPE (Wallonia), BRUGEL (Brussels), CREG (federal). This is general knowledge, not from peasy.be: verify with Legal.
  • Peasy is paid a referral fee by partners and the customer signs with the supplier, so ranking must stay neutral and be explained on the results page.
  • The FR site has a thinner energy section than the NL site, so FR copy is parked as [FR: todo].
  • Energy and telecom also live on sister brand Aanbieders.be (e-Contract BV). Not in v1.

Scope

In scope

  • Nightly tariff sync from the supplier's API
  • Mapping and validation into Peasy's energy comparison model
  • Supplier shown in results for Flanders, Wallonia and Brussels on peasy.be (web)
  • Neutral ranking by price for the customer's usage
  • Switch submitted through the supplier's order API
  • Hide the supplier and alert ops when data is stale or the feed fails
  • Back-office: activate or deactivate the supplier, logo, ops contact

Out of scope

  • Aanbieders.be, Hypotheek.winkel, Verzekeringen.be
  • Commission or commercial weighting in ranking, and any "new" label or priority placement
  • Real-time price calls per comparison
  • Telecom suppliers
  • Mobile app

User stories

S1 Sync supplier tariffs every night

5 pts

As the energy engine, I want to pull the supplier's tariffs every night from its API, so that results show current prices.

Given the supplier is active When the nightly job runs Then all its electricity and gas products for the regions it serves are fetched and stored with a "fetched at" timestamp.
Given a product disappears from the API response When the sync completes Then that product is marked inactive and no longer shown.
Given the API times out or returns an error When the job retries [N] times and still fails Then the run is logged as failed and the last good data is kept (but not shown, see S4).

S2 Map and validate tariffs

5 pts

As the energy engine, I want supplier fields mapped and validated against Peasy's comparison model, so that yearly cost is calculated the same way for every supplier and region.

Given a product from the API When it is mapped Then it has product name, fixed or variable, € per kWh (per meter type), fixed fee per year, green %, contract length, region and valid from/to.
Given a required field is missing or out of range (negative price, unknown meter type, unknown region) When validation runs Then the product is rejected, logged with the reason and not shown.
Given the supplier sends the same product with different prices per region When mapping runs Then one regional tariff is stored per region and none leaks into another region.
Given the supplier sends extra fields Peasy doesn't model When mapping runs Then they are stored raw but not used in ranking.

S3 Show the supplier in results

5 pts

As a household comparing energy, I want to see the new supplier's offers next to the others, so that I can pick the cheapest deal for my usage.

Given I complete the energy flow with a postcode in Flanders, Wallonia or Brussels When results load Then the supplier's offers for my region appear, sorted with the rest by price for my usage.
Given an offer card When it renders Then it shows supplier name or logo, product name, yearly cost "€ XX per jaar", € per kWh, fixed fee, green %, tariff type and contract length (OfferCard).
Given the supplier's offer is not the cheapest When results load Then it sits in its price position with no label, badge or priority.
Given the supplier doesn't serve my region When results load Then it is not shown and the rest of the list is unchanged.
Given offers are still loading When the page renders Then I see placeholder cards and "Aanbiedingen worden geladen…" (proposed).

S4 Hide the supplier on stale data

3 pts

As Peasy ops, I want a supplier with stale or failed data hidden automatically and flagged to me, so that customers never switch on a wrong price.

Given the last successful sync is older than [N] hours When a comparison runs Then the supplier's offers are excluded and the list shows the other offers without an error message.
Given the supplier is hidden When that happens Then ops get an alert (channel TBD) with supplier, last success time and error.
Given the next sync succeeds and passes validation When the data is stored Then the supplier reappears without manual action.

S5 Submit the switch via the order API

8 pts

As a customer, I want to confirm my switch on Peasy and have it sent straight to the supplier, so that I don't have to sign up again elsewhere.

Given I chose an offer When I open "Controleer je overstap" Then I see a recap, my delivery address, email, EAN code(s), the earliest start (35-day notice), region info and an unchecked consent checkbox.
Given an EAN code isn't 18 digits or the consent isn't checked When I press "Bevestig overstap" Then I see an error summary, inline errors per field, focus moves to the first error and nothing is sent.
Given valid input When I confirm Then Peasy re-checks that the price is still current, sends the order to the supplier's API and stores the supplier's order ID with a Peasy reference.
Given the price changed since the results page When I confirm Then I see the new price and must confirm again.
Given a network retry or double click When the order is sent twice Then the supplier receives one order (idempotent on the Peasy reference).
Given the optional marketing checkbox When the page loads Then it is unchecked and doesn't block the switch.

8 pts is the ceiling. Split into "confirm form" and "order API client" if grooming estimates higher.

S6 Confirmation and fallback

3 pts

As a customer, I want a clear confirmation of what happens next, and a way forward when the order can't be sent, so that I trust the switch is handled.

Given the supplier's API accepts the order When the confirmation page loads Then I see "Je overstap is aangevraagd", my Peasy reference, the next steps and I get a confirmation email.
Given the order API is unreachable or rejects the order When I confirm Then I see "Je aanvraag is niet doorgegeven", my current contract stays unchanged, nothing is counted as placed and I see an error code for customer service.
Given the failure screen When I press "Probeer opnieuw" Then the order is retried with the same Peasy reference.
Given the failure screen When I choose "Laat ons je terugbellen" Then ops get a callback task with my details and reference. (Callback confirmation screen: proposed, not in the mockup.)
Given the supplier rejects the order later (asynchronously) When Peasy receives the status Then ops are alerted and the customer is contacted. [Status webhook: TBD]

S7 Manage the supplier in the back-office

3 pts

As Peasy ops, I want to activate, deactivate and configure the supplier in the back-office, so that we control when it goes live.

Given I open the supplier list in the back-office When I add the supplier Then I can set name, logo, API credentials reference, regions served, ops contact and status.
Given the supplier is "Niet actief" When a comparison runs Then it is never shown, even with fresh data.
Given no logo is uploaded When I try to activate Then activation is blocked with "Voeg eerst een logo toe."

Non-functional

  • Privacy: name, address, EAN and contact details go to the supplier to carry out the switch the customer asks for. Controller Verzekeringen NV; the supplier is a separate controller. Retention per existing policy. Marketing opt-in is never pre-checked. Update the privacy notice to list the supplier as a recipient. [Legal text: todo]
  • Regulation: check switching and comparison-transparency rules for each region (VREG, CWaPE, BRUGEL) and what "jaarkost" must include. Verify with Legal.
  • Security: supplier API credentials in the secrets store, never in the admin UI; TLS; order calls are idempotent and retry-safe.
  • Accessibility: WCAG 2.2 AA; error summary focused on submit; inline errors linked to their fields; visible focus ring; loading state announced as status.
  • Performance: results never call the supplier's API live; order submit answers or falls back within [X] s.
  • Analytics: supplier_sync_success, supplier_sync_failed, supplier_hidden_stale, offer_selected, switch_confirmed, switch_order_accepted, switch_order_failed, callback_requested.

Dependencies

  • Signed partner agreement with the supplier, including API access (tariff and order) and a sandbox
  • Supplier API docs: tariff schema, order schema, status callbacks, rate limits, regions served
  • Logo usage rights from the supplier
  • Legal review: consent wording, privacy notice, regional regulation, ranking explanation (NL + FR)
  • Ops: alert channel and process for failed or rejected orders and callbacks
  • A back-office place to manage suppliers (existing or new, see open questions)

Assumptions

  • Assumption: Peasy's energy engine already calculates yearly cost from € per kWh, fixed fee and usage; this epic only feeds it new data.
  • Assumption: The supplier's API exposes tariffs per meter type and per region, and returns an order ID synchronously.
  • Assumption: Grid costs and levies are added by Peasy's engine, not by the supplier.
  • Assumption: The existing confirm step can be reused; only the hand-over changes from manual to API.
  • Assumption: When the order fails, the customer's current contract is unchanged and nothing is counted as placed.

Open questions

  1. What exactly is in "jaarkost" (energy, grid costs, levies, btw), and does any regulator require a specific breakdown per region? Owner: Legal + Product
  2. Does the order API return a final status synchronously, or do we need a webhook or polling for later rejections? Owner: Tech
  3. What is the stale-data threshold, and which alert channel does ops use? Owner: Ops + Tech
  4. Consent wording: does the customer accept the supplier's terms on Peasy, or does the supplier send its own contract to sign? Owner: Legal
  5. Which basis does the "Laagste prijs" badge use, and may a "new" tag ever be shown under neutral ranking? Owner: Product + Legal
  6. Does a back-office supplier list already exist, or is it new work? Owner: Tech
  7. What is the monthly switch target for success? Owner: Product
  8. When do Aanbieders.be and the other sister brands follow, and does the Meilleurtaux deal change that? Verify with Peasy. Owner: Product
